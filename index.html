Splashboard

A swim meet’s results, live. Used by about 260 people.

Open splashboard.in View the code

Our local swim meet was still running its results on paper. As a former swimmer, I knew exactly where that breaks down, so I designed and built a live timing app, and it ran the whole meet.

Several officials time races at once from their own phones. Results reach everyone in under a second, and each person sees and changes only what their role allows.

Since the meet, I’ve kept building it into a multi-meet platform with swimmer and coach profiles, co-organisers, relay teams, certificates and entry payments.

  • ~150swimmers
  • ~100spectators
  • 10officials
  • < 1 sfor results to reach everyone

All of it, from the first commit. On meet day (June 21), it had:

  • The interface, a vanilla JavaScript PWA with an offline queue so timers keep working without signal
  • The PostgreSQL data model, with Row Level Security on 10 core tables and role-scoped QR logins by magic link
  • Live results over Supabase Realtime, plus a Cloudflare Durable Object that fans results out to spectators’ phones over WebSockets
  • Web Push notifications, signed with VAPID on the Web Crypto API
  • A GitHub Actions deploy to Cloudflare Workers, and I kept shipping fixes through the meet itself

Since then:

  • More than 40 SQL migrations, with Row Level Security now on 37 tables
  • Razorpay payments for entry fees, with signature-verified webhooks
  • A build step that minifies and content-hashes the assets

I built it on Supabase with only a thin Cloudflare Worker, so every access rule had to live in the database. I chose Postgres Row Level Security (10 core tables at launch, 37 now) over writing authorization code in a server. That gave up some flexibility, but it kept the rules in one place. A timer can’t approve a result, even if someone edits the client code or calls the API directly.

Four habits, each from something I actually ran into.

Check the output against the source.

At Galent, an agent said it found 10 POST handlers. I counted, and there were 4. A confident answer isn’t evidence, so if I can check it, I check it.

Something has to be able to say no.

A coding agent once marked its task done for code that had never been compiled. Now I want a compiler, a test or a person at every gate. My access-control guard test fails the build if a new page ships without a decision.

Measure, then claim.

My 59-check suite gave me an honest number to compare two apps: 52 against 59. I also wrote down the one check of my own that gave a false pass, instead of hiding it.

Go to where the people are.

I spent time on-site at steel forges before deciding what a robot should do, and I designed Splashboard around officials working under time pressure. The best ideas started with watching someone work.

Reliable

I care most about the gap between a good demo and a system people can depend on.

Close to users

I want to work where the software meets the people using it, like the forge operators and swim meet officials I built for.

An owner

I own what I build, from the first commit to the first users. Splashboard was my idea, and I ran it on race day.
